# Authoritative mutation boundary

`contracts.py` defines immutable intent, validation receipts, confirmation, one physical execution attempt, reconciliation reservations, domain outcome and a separate typed sidecar presentation. `service.py` owns generic lifecycle orchestration; `transitions.py` is enforced by the canonical repository. `registration.py` validates executable adapters and independently checks application declaration and narrowing policy. No operation names occur in generic control flow.

To install an operation, declare it on `ApplicationDefinition.mutation_operations`, allow that exact ID/version through sidecar policy, and contribute an adapter under `(application_id, operation_id, version)` through the existing installed contribution catalog. Its strict Pydantic payload model must forbid extras and preserve canonical input bytes. Changing operation semantics or payload schema needs a new version/schema identity; retain old versions while operations remain outstanding. Missing or mismatched implementations fail closed. Current domain applications declare no writes.

The adapter receives verified request owner/acting identity and an exact target. A domain adapter may obtain the short-lived verified delegated token through the existing request context, but must never serialize credentials. `authorize` checks current domain authority before reads/validation/effect. `validate` returns an exact intent digest, validator identity/version, preview, current permission dependencies, exact expected revision and expiry. Validation must resolve source truth; caller-provided snapshots/provider labels are candidate provenance, not proof. `execute` must atomically recheck identity, authorization/permission epochs, source freshness, validation/confirmation binding/expiry and exact authoritative entity version, deduplicate the domain operation key with the write, and retain an authoritative receipt. Generic preflight cannot replace this transaction. Any transport failure can follow an effect; no hidden resend is permitted.

Postgres reserves before sending. There is one execution attempt per proposal, with a 60-second operational lease; after interruption/timeout, `reconcile` only observes the original key. An absent receipt stays uncertain, including when no send occurred. Reconciliation may repeat under separate CAS reservations; there are no automatic worker retries. Even if an execution is still running beyond its lease, reconciliation never sends and can safely race its eventual receipt; the losing local commit reloads through status recovery. All domain reads remain authorized. Revoked write policy cannot prohibit authorized observation-only reconciliation. Domain deduplication/reconciliation lifetime must cover retained AI metadata, including expiry and restart. Applied/rejected/expired are terminal.

Source dependencies use `ContextPermissionRevalidatorRegistry`; unknown dependencies fail closed. Canonical proposals are private control metadata and must never be injected into models/memory/artifacts as authoritative state. The API uses `present()` to expose a typed projection: pending patches/previews require current dependencies; outcome/status views omit them and expose domain-authorized post-state references only. This handles an operation legitimately changing its own source revision. Classification is conservatively restricted for every candidate, irrespective of caller labels. The phase creates no inference calls.

The persistence factory installs `PostgresMutationRepository`; migration 025 owns heads and immutable audit revisions in one aggregate. Scoped reads bind owner, acting identity, application and workspace in SQL. CAS reservation plus owner lifecycle locks/fences serialize metadata and deletion. Account export includes both record families. Fenced purge removes AI heads/audit only, never authoritative external state. Metadata and operation identities are retained until owner deletion; there is no premature TTL/idempotency eviction. Bulk payloads are rejected rather than stored here.

Offline conformance lives in `tests/test_mutations.py`; deferred Postgres tests live in `tests/persistence/test_mutations.py`. These prove different boundaries. Synthetic receipts never establish deployed domain authorization, persistence, identity, or cloud acceptance.
