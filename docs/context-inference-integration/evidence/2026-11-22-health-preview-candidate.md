## Candidate receipts

The test authority receives one in-process operation from the synthetic caller and consumes its nonce for the verified PAS actor, registered client, expected method/path, original key, canonical request digest, enrollment and frozen target. Create retry needs a fresh operation for the same intent. Preview requires the same enrolled selection and target and the original create-to-conversation binding. A preview key may be submitted once. The fixture implements no preview status or outward content recovery. The nonce and branch checks model decision points for an approved authority boundary.

The test signature uses Ed25519 and compact, sorted-key UTF-8 JSON with duplicate members rejected. The header carries base64url of the statement and detached signature, separated by a period. The signed fields include purpose-specific schema version, issuer, audience, algorithm, key ID, bounded issue and expiry times, method and path, original create and operation keys, normalized JSON request digest, SHA-256 of the exact response bytes, actor/client/owner/installation, enrollment generation, selected profile and frozen target. Preview adds the active branch digest, actual source revision, Health permission version, sensitivity, source and memory grant versions, application policy and source epochs, inventory digest, confirmation and destination. Candidate validity is at most 30 seconds and preview receipts also expire by the frozen preview expiry. The receiver pins these expected fields and rejects altered bytes, timing, audience, key, purpose, signature, destination and selection. The identifiers in the receipt header are sensitive metadata. The response JSON contains only the preview metadata.

## Scope of the witness

The opt-in native Health witness launches one pinned Health process, passes source requests and PostgreSQL-generated original keys over private pipes, and runs the real PAS HTTP handlers in process. The Health database is disposable and uses a Unix-domain socket. PAS authority, conversation, branch, source grants and memory storage in this Health witness are fixture-backed. It exercises normal PAS policy and canonical memory code. The source reads use Health's exact projection and current version verification. The Health journal has no receipt-adoption operation at this revision.

Two draft contract gaps prevent a direct product join. Health's reservation type expects a UUID for the PAS owner while Google PAS owners are opaque `usr_…` strings. The witness supplies a synthetic UUID to the Health test journal and independently verifies the real PAS owner representation at PAS. Health's local create digest must be supplied before it allocates the original key, so the witness uses a pre-key local digest and binds the actual PAS request later. Final device acquisition of PAS-audience proof, enrollment lifecycle, callback service authentication and routing to the live Health request, and receipt key lifecycle require agreement. Private pipes and fixture claims establish none of those product properties.

Bound continue reaches the existing denial before replay and receives HTTP 422. The tests check zero runtime handoff bytes and zero fake provider POSTs. Scoped SDK and native Travel witnesses exercise compatibility separately. No integrated restore, native device, or external eligibility is established. Dispatch remains `BLOCKED_CONTRACT` and production remains `NO_GO`.

Rollback omits the isolated composition. Future durable receipt adoption would require independent current-generation evidence after restore, with stale or ambiguous binding rows quarantined. Existing source locks remain release gates.
