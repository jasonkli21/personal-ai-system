The maintainer authorized a hermetic local slice. The selected app is Personal AI Local Bridge, serving one PAS owner in the standalone `personal_ai` application. The synthetic turn uses active PAS chat history and protected temporary files. The PAS reservation uses the in-memory repository implementation and the bridge send fence uses real POSIX storage and process locks. The fixture runs the production assembler, Ed25519 grant verification, OAuth/JWKS validators, text serializer and SSE parser. The provider actions are observed at injected HTTP transports. No real sign-in, registration, refresh, catalog, inference or billable action was performed.

At entry, the operator used local JSON to build live OAuth and Responses clients for paired execution. The pairing pinned origin and connection while leaving PAS scope to the signed package. The SSE failure and incomplete handlers could compare two missing response IDs as equal. Terminal receipt cleanup discarded the key after the original proof expired. Existing lifecycle and dispatch tests covered most protocol and recovery cases. The added witnesses exercise these gaps with the same validators and persisted identities.

## Live blockers

- The project maintainer needs written provider/program eligibility for the exact Personal AI Local Bridge registration and user-controlled distribution. The selected account, OpenAI workspace, PAS workspace and host must be independently bound. The verified ID-token issuer, subject and issued client are the local account identity. The access-token subject equality check remains conservative because a cross-token subject mapping lacks accepted evidence. [Open-source distribution and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference), [SIWC Terms](https://openai.com/policies/sign-in-with-chatgpt-terms/).
- The project maintainer and independent reviewer need provider-enforced zero-credit consumption for the exact request, app, account/workspace and registration, including settings changes through dispatch. Usage settings, catalog visibility, a local output cap and a zero cash invoice are insufficient. The account owner would separately authorize any bounded live trial after eligibility and credit enforcement are established. [Plan and credit controls](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites), [models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).
- The independent reviewer owns E1 acceptance of the candidate revision and its pre/post-commit race and recovery evidence. The project maintainer owns any later live E2 submission. Hosted use and shared token custody require separate provider approval. Production remains `NO_GO`. [Delivery ledger](../delivery-and-acceptance.md#promotion-gates).
