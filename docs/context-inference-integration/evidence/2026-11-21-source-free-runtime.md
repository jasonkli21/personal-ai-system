## Changes and execution path

- [Bridge runtime](../../../backend/src/personal_ai/local_bridge/runtime.py) adds a private in-process entry to the existing generator. The foreground fixture supplies its confirmed routing root as a trusted argument. The grant keeps the v1 `LocalChatScope` and registered Ed25519 signer. The verifier binds the issued grant to the original package, caller and expiry. Current root authority binds the approval, purpose, app, owner, client, host and installation to that package. Registration is checked before snapshot and again inside snapshot and at send-start. The package hash covers the model, connection revision, original scoped reservation, context, limits and text. The local adapter supplies the fixed destination.
- Dispatch flows from `_require_dispatch` through snapshot, model discovery, `store.claim`, and `mark_send_started` to `ChatGPTResponses.stream`. Under the store lock, send-start checks current root, policy, registration, credential snapshot and expiry before persisting the independent fence. Existing application-plan grants retain their own fence selection. The public `execute` path supplies no foreground root and retains the existing standalone v1 behavior. The foreground argument has no route, config or IPC field.
- [Local turn tests](../../../backend/tests/test_chatgpt_local_turn.py) exercise the shared assembler, one explicit owner confirmation, the existing gate, signed v1 dispatch, actual serialized mock HTTP and PAS finalization for the fixed synthetic message “Reply with the word blue.” The foreground conversation starts empty. [Bridge tests](../../../backend/tests/test_chatgpt_bridge_transport.py) count observed mock POSTs independently of the workers' result messages and cover real POSIX locks, process death, rollback, expiry, uncertain streams and transport denial.
- [Private HTTP tests](../../../backend/tests/test_private_application_plan_http.py) retain v1.2.0 consumer routes and test the caller-owned journal against separately installed clients. The synthetic caller writes and syncs the bound create UUID/title, conversation ID and preview intent, then confirmed continuation before its POST. Recovery checks the original target, app, owner, actor, verified client namespace and workspace. It repeats only the create with its stored inputs. Lost continue and 429 cases use the original continuation key for GET status, preserve uncertainty on a missing status, and read authorized detail for the matching completed message. The app-facing schema, SDK version, endpoint inventory and delivery composition have no changes.

## Independent review and disable procedure

Review the result range and rerun the foreground and installed compatibility witnesses. Check the exact v1 signature binding, the order of lock-held authorization and fsynced fence before transport, and the externally observed counter after crash and receipt rollback. Inspect the separate private scope and installed-client controls. Record an independent A decision and reopen it if the disposition of an inherited assumption changes. Dated source identity and sealed evaluation failures remain with their owning evaluation reviews.

Disable the foreground composition by removing its invocation or withdrawing current root approval and keeping the affected installation quarantined. No production setting enables it. Preserve revocation state, protected caller journals, receipts, fences and original keys. Where an installation or its authority directory is known lost or restored, withdraw approval and keep pending attempts closed. An intact independent fence is required for the receipt-rollback witness. Cross-store disaster recovery, confidential PAS delivery and physical host recovery belong to R3.
