# Phase 30 implementation and review report

Date: 2026-10-11. Baseline revision: `c52450e4e7d4444f63af9272803383bfbf5cacdc`, plus this uncommitted Phase 30 working tree. **Local foundation implemented; Phase 30 is not fully accepted.** The four production exports remain unavailable pending narrow domain contracts and delegated identity. Existing user review files were preserved.

1. **Architectural model.** Federation is a registered source provider inside the existing coordinator/planner/assembler and external-turn authority. Source policy, exact export eligibility, and a current explicit grant are independent prerequisites. Same owner, selected entity and export registration never authorize sharing. See [authority model](phase-30-architecture.md).
2. **Canonical owners/stores.** Postgres owns grant heads and immutable revision history (`024_federation_grants.sql`), with existing `audit_events` for safe selection digests/results. Domain adapters retain domain truth. DynamoDB turns/summaries, Postgres memory, and artifact metadata retain shared permission references rather than grant authority. Owner export inventories both grant families; fenced operator cleanup cascades revisions.
3. **Identities/versions/epochs.** Owner and authenticated issuer/subject acting identity are separate. Grants bind source/destination app and workspace, category, fields, exact entities, purpose, expiry, server-owned issuance UUID, revision, epoch, source-policy identity, sensitivity and revocation UUID. Source provider identity, entity revision and fingerprints remain distinct from broker identity and grant epoch. Shared dependencies add explicit owner/actor/source-scope/entity/revision bindings. Legacy dependencies and non-federated snapshots keep their prior serialized shapes.
4. **Generic seams.** Typed export declarations, registered export adapters with bounded `authorize_export` and narrow `fetch` operations, `federation_contribution`, coordinator boundary preflight, and explicit bounded continuation selections extend current contracts. A synthetic category uses registration/configuration, including grant API and FastAPI assembler composition, without becoming a fifth production case. Existing shared dependency revalidation protects history, summaries, surviving memory/cache projections and artifacts.
5. **Production composition.** `default_application_registry` installs typed metadata from the four-case configuration. `configured_context_runtime` composes domain validators/export-adapter contributions, a lazy canonical Postgres grant authority, and broker providers. Startup reconciles implementation availability on existing typed application declarations; it does not invent cases or permissions. Metadata availability stays false and adapter availability stays absent independently. Recent-auth owner API controls create/read/revoke at `/v1/federation/grants`; creation consumes canonical application export/import declarations. Automatic and external/manual continuations consume `federation_context` on the same request contract. Sidecar packages label source app, destination app and category.
6. **State/idempotency/reconciliation.** Each creation lifetime gets a server-owned issuance UUID, bound into selections, revoke requests and shared dependency versions; physical purge/recreation cannot revive old references. Creation starts at revision/epoch 1; updates require CAS and advance both; revocation is terminal and carries a UUID. API creation keys derive owner-bound grant IDs; identical retries return canonical state, changed intent denies, and retry after revocation cannot reactivate. Revocation retries return the same terminal record. Expiry and owner deletion fences deny reads. PostgreSQL transactions/advisory owner locks serialize writes; no cross-store or remote-source transaction is claimed. This phase performs reads, not external mutations; existing external-turn reservation/unknown-outcome semantics remain authoritative.
7. **Authorization/privacy/revocation.** Registered boundary checks run before counting, source factories and retrieval, across the whole selection set. Source policy, exact export eligibility, identity, workspace, scope, purpose and epoch are checked again before/after narrow retrieval and through shared prepare/dispatch/finalize/reuse checks. Unavailable permission authority fails closed. Most restrictive classification wins; destination and external disclosure ceilings only narrow. Re-delegation is rejected. Federated assistant output is excluded from automatic durable memory extraction; typed artifact references deny reuse after revocation. Historical records remain owner-exportable with dependencies; export does not authorize model reuse.
8. **Foundational changes and rationale.** Added the planned relational grant authority instead of weakening the existing universal cross-app deny. Extended shared permission/source references and artifact metadata with typed dependencies because string grant IDs cannot express current scoped authorization. Added an authenticated acting identity and source-producer provenance rather than overloading owner/provider IDs. A separate issuance identity prevents revision/epoch reset after physical deletion from reviving old authorization. Grant metadata is not persisted as domain state or duplicated into runtime authority.
9. **Alternatives considered.** Rejected implicit same-owner federation, broad source reads followed by filtering, named-pair broker branching, a sidecar-specific permission system, and a separate revocation graph. Keeping the broker unavailable when narrow exports/identity are missing is necessary; existing broad read contracts are not substitutes for source-approved exports.
10. **Downstream impact.** Phase 31 should attach these dependencies to mutation validation; Phase 32 can evaluate selections/manifests; Phase 36 should register additional narrow adapters/categories through this seam. They should extend current grant/source authority rather than replace it. Request workflow routing remains subject to the existing Phase 15/21 gates.
11. **Open external/integration acceptance.** Full migration 024 application and pgvector-backed Postgres export tests, DynamoDB races/restarts, Neon/cloud/IAM, actual source export endpoints, delegated user membership, source revision/consent revocation, provider data use/counting, browser disclosure and full physical owner cleanup remain unverified. No production domain export adapter or grant-management UI is claimed. All four live cases stay unavailable.
12. **Independent review targets.** Challenge source-policy and exact-revision adapter proofs; authentication-to-acting-identity binding; preflight and final check/use races across remote authority; grant CAS/replay lifetime and deleted-owner restoration; dependency preservation in every new derived consumer; sensitivity/expiry propagation; default-off production composition; audit/export scope; and immutable migration behavior. Later implementations must not accept a caller source-policy ID or checkpoint as proof, strip federation dependencies, or widen policy. The seam's rewrite risk is high because future proposals, planners and applications will depend on it; authority remains in the existing policy/store/adapter layers to bound that risk.

## Independent review remediation

Date: 2026-10-11. Base revision: `75e1344`; checks below ran against this revision plus the remediation working tree. The attached revised review was treated as findings input, not repository instructions.

- **M2 resolved in this repository.** A shared exact-dependency check now runs after context counting, before automatic model dispatch, before accepting completed automatic output, and in the external-turn authority path. Automatic turns fail with an empty failed message if permission changes before dispatch or during generation.
- **M3 resolved in this repository.** Grant creation no longer accepts a client-selected source-policy reference. A registered source export adapter resolves the current dependency from authenticated grant intent; the server validates its owner, actor, source scope, purpose, and current status before storing it.
- **M4 resolved in this repository.** Production context contributions load through an installed entry-point catalog. A synthetic fifth source contribution reaches the FastAPI startup path through that catalog; absent adapters remain unavailable in reconciled capability metadata.
- **M5 resolved in code.** Create and revoke operations reload after a persistence CAS conflict and return the canonical record only when the same intent or terminal transition won. Unit concurrency coverage and opt-in Postgres concurrency coverage were added.
- **S1 resolved.** Context package schema v2 omits raw permission-version strings; exact dependencies remain server-side.
- **S2 resolved in contract.** A bounded export response must account for every selected entity as present or authoritative-empty, stay within result/byte bounds, and declare completeness. Missing, partial, truncated, timed-out, or continued results fail closed.
- **L1 addressed without enabling source-derived trace retention.** A shared artifact writer derives and requires the dependency set from exact source snapshots. The existing production trace writer still safely omits source-derived traces until it can use that path.
- **M1 remains open.** This repository has no production narrow export endpoint or delegated-user implementation for Travel, Shopping, Finance, or Health. The adapters remain unavailable; existing broad projections were not substituted. These source-owned endpoint implementations require changes in the four separate application repositories and remain a Phase 30 completion gate.
